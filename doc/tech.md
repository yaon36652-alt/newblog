## 1. 技术选型

推荐一套"**一个项目搞定前后端**"的方案：

| 技术 | 干什么用 | 为什么选它 |
| --- | --- | --- |
| **Next.js**（App Router） | 页面 + 接口都靠它 | 一个工程同时管"给访客看的网页"和"给后台用的接口"，不用拆两个项目 |
| **TypeScript** | 写代码的语言 | 编译阶段就能揪出拼错字段、传错类型这类低级错误 |
| **Tailwind CSS** | 写样式 | PRD 要求响应式设计，它的 `sm:`/`md:`/`lg:` 断点写法做手机/平板/电脑适配非常顺手 |
| **Prisma + SQLite** | 操作数据库 | SQLite 就是个文件，零安装零配置，个人博客这点数据量完全够用；以后想换 MySQL，只改一行配置 |
| **bcrypt** | 密码加密 | 登录用的密码绝不存明文，存的是哈希值 |

> 备选：如果更熟悉 Vue 生态，也可以 **Vue3 + Vite + Express + MySQL** 前后端分离，但要维护两套工程、多一次部署，个人博客来说偏重了。

## 2. 架构规范（项目里的"规矩"）

- **三层分工**：页面组件只负责"长什么样" → API 路由负责"业务逻辑"（校验、查库）→ Prisma 负责"读写数据库"。互不越界，出了问题好定位。
- **两套布局**：用户端和管理后台用各自的 Layout（导航栏、底色都不一样），但共享文章卡片、页脚这类公共组件。
- **"门卫"机制**：所有 `/admin` 开头的后台页面，进入前先过一个中间件（middleware）检查登录状态——没登录的人直接弹回登录页，拦在门口。
- **密码安全**：登录时 bcrypt 比对哈希；登录成功后发一个 httpOnly 的会话 cookie，浏览器每次请求自动带上。
- **代码规范**：ESLint + Prettier 统一格式，组件文件用大驼峰命名（`PostCard.tsx`），接口文件按资源命名。

## 4. 路由设计（网址和页面的对应关系）

### 用户端（公开，谁都能看）

| 网址 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页 | 文章列表，按时间倒序，分页 |
| `/posts/[id]` | 文章详情 | 按 id 查一篇文章全文 |
| `/about` | 关于我 | 博主介绍 |

### 管理后台（需登录）

| 网址 | 页面 | 说明 |
| --- | --- | --- |
| `/admin/login` | 登录页 | 账号 + 密码 |
| `/admin` | 仪表盘 | 文章总数、本月新增等统计卡片 |
| `/admin/posts` | 文章列表 | 表格 + 搜索框 + 新建按钮 |
| `/admin/posts/new` | 新建文章 | 标题、摘要、正文表单 |
| `/admin/posts/[id]/edit` | 编辑文章 | 同上，回填旧内容 |

### 接口（页面背后调用的 API）

| 接口 | 作用 | 权限 |
| --- | --- | --- |
| `POST /api/auth/login` / `logout` | 登录 / 登出 | 公开 |
| `GET /api/posts` | 文章列表 | 公开 |
| `GET /api/posts/:id` | 文章详情 | 公开 |
| `POST /api/posts` | 新建文章 | 仅登录 |
| `PUT /api/posts/:id` | 更新文章 | 仅登录 |
| `DELETE /api/posts/:id` | 删除文章 | 仅登录 |
| `GET /api/stats` | 仪表盘统计 | 仅登录 |

## 5. 数据库 Schema（三张表）

### User —— 管理员账号

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | 自增整数 | 主键 |
| username | 字符串（唯一） | 登录账号 |
| passwordHash | 字符串 | bcrypt 加密后的密码 |
| createdAt | 时间 | 创建时间 |

### Post —— 文章

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | 自增整数 | 主键（就是网址里的 `[id]`） |
| title | 字符串 | 标题 |
| summary | 字符串 | 摘要（首页卡片展示） |
| content | 文本 | 正文（Markdown，详情页渲染） |
| createdAt / updatedAt | 时间 | 创建 / 更新时间 |

### About —— 关于我

只有一行数据的单行表（头像地址、简介、联系方式），给未来"后台编辑关于我"留口子；第一版如果求快，也可以先写死在页面里。

> 第一版不建评论表——PRD 里没提评论功能，先不做，保持简单。

## 6. 实现步骤（按依赖顺序推进）

1. **初始化工程**：`create-next-app` 建项目，装好 Tailwind、Prisma 等依赖，跑通空页面。
2. **建数据库**：写好 `schema.prisma`，`prisma migrate` 生成表；写个种子脚本造几条假文章，方便后面调试。
3. **搭公共骨架**：全局布局 + 导航栏、页脚、文章卡片组件，先保证用户端和管理后台两套外观能分开渲染。
4. **做用户端三页**（纯展示，最简单，先做它能快速看到成果）：首页拉文章列表 → 详情页按 id 渲染 Markdown → 关于我页面。
5. **做登录闭环**：登录页 + 登录接口（bcrypt 比对、发 cookie）+ middleware 门卫，验证"没登录访问 /admin 会被弹回"。
6. **做文章管理**：后台列表（查 + 搜索）→ 新建表单 → 编辑表单 → 删除（带二次确认弹窗），这四件事共用一套接口。
7. **做仪表盘**：统计接口查出总数、本月新增等数字，卡片展示，加"去写文章"快捷入口。
8. **响应式收尾**：手机宽度下导航折叠、列表单列、后台表格可横向滑动，逐屏核对 PRD 的适配标准。
9. **整体走查**：清空数据，模拟一个真实访客 + 一个真实博主各走一遍完整流程。
